Guía de instalación · Paso a paso

Conecta TradingView con Claude, sin atajos y sin misterio.

Esta guía te acompaña desde cero: instalar Python, levantar el servidor, exponerlo a internet y registrar las herramientas en Claude Desktop. Escrita para que cualquier persona pueda seguirla, incluso sin experiencia previa en terminal.

01

Antes de empezar

Qué es cada pieza, qué necesitas tener instalado, y un glosario para que ningún término te detenga.

¿Qué vas a construir?

Un puente entre tus gráficos y tu asistente

TradingView puede enviar un mensaje automático (una alerta) cada vez que tu estrategia genera una señal de compra o venta. Este proyecto instala un pequeño programa en tu ordenador que escucha esos mensajes, los guarda en una base de datos, y se los muestra a Claude cuando se lo pidas. Así puedes preguntarle cosas como "¿cuántas señales de compra generó mi estrategia hoy?" y obtener análisis reales.

Requisitos

Lo que necesitas

  • Un ordenador Mac, Windows o Linux
  • Python 3.10 o superior
  • Cuenta de TradingView (plan Essential+ para webhooks)
  • Claude Desktop instalado
  • 30–45 minutos de tu tiempo
Glosario express · si un término no te suena, está aquí
TerminalLa ventana de texto donde escribes comandos. En Mac se llama Terminal (búscala con Cmd+Espacio). En Windows, busca PowerShell en el menú inicio.
WebhookUna "llamada automática" entre programas. TradingView marca el número (la URL de tu servidor) cada vez que hay una señal, y le deja un mensaje con los datos.
MCPModel Context Protocol. El estándar que permite a Claude usar herramientas externas, como consultar tu base de datos de alertas.
SQLiteUna base de datos que vive en un solo archivo en tu disco. No hay que instalar nada extra: Python ya la incluye.
localhostUna dirección que significa "este mismo ordenador". Cuando algo corre en localhost:8000, solo tu máquina puede verlo.
02

Instalación, paso a paso

Siete pasos. Cada uno con sus comandos exactos, qué deberías ver en pantalla, y qué hacer si algo falla.

1

Verifica que tienes Python

≈ 2 minutos

Abre tu terminal y escribe el siguiente comando. Pulsa Enter después de escribirlo (esto aplica a todos los comandos de esta guía).

terminal
$ python3 --version
Python 3.12.4

Si ves un número 3.10 o superior, perfecto: continúa al paso 2.

No tengo Python o me sale un error, ¿qué hago?

Mac: instala Homebrew desde brew.sh y luego ejecuta brew install python.

Windows: descarga el instalador desde python.org/downloads. Durante la instalación, marca la casilla "Add Python to PATH" (es fundamental, no la omitas).

Linux: ejecuta sudo apt install python3 python3-pip python3-venv.

Cierra y vuelve a abrir la terminal después de instalar, y repite la verificación.

2

Descarga el proyecto y entra en la carpeta

≈ 3 minutos

Coloca la carpeta tradingview-mcp (la que descargaste de esta conversación) en un lugar fácil de recordar, por ejemplo tu carpeta personal. Luego navega hasta ella desde la terminal:

terminal
# Mac / Linux:
$ cd ~/tradingview-mcp

# Windows (PowerShell):
$ cd $HOME\tradingview-mcp
Consejo El comando cd significa "change directory" (cambiar de carpeta). Si te pierdes, escribe pwd (Mac/Linux) para ver dónde estás, o ls para listar los archivos de la carpeta actual. Deberías ver src, tests, requirements.txt, etc.
3

Crea un entorno virtual e instala las dependencias

≈ 5 minutos

Un entorno virtual es una caja aislada donde se instalan las librerías de este proyecto sin tocar el resto de tu sistema. Es la práctica recomendada y evita el 90% de los problemas.

terminal · dentro de tradingview-mcp
# 1. Crear el entorno (solo se hace una vez)
$ python3 -m venv .venv

# 2. Activarlo — Mac / Linux:
$ source .venv/bin/activate

# 2. Activarlo — Windows PowerShell:
$ .venv\Scripts\Activate.ps1

# 3. Instalar las librerías del proyecto
$ pip install -r requirements.txt

Cuando el entorno está activo, verás (.venv) al principio de la línea de tu terminal. La instalación tarda uno o dos minutos y termina sin mensajes de error en rojo.

Windows me dice "ejecución de scripts deshabilitada"

Ejecuta este comando una sola vez y vuelve a intentar la activación:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Es una medida de seguridad de Windows; con esto permites scripts firmados localmente.

¿Tengo que activar el entorno cada vez?

Sí: cada vez que abras una terminal nueva para trabajar con el proyecto, repite solo el paso de activación (source .venv/bin/activate). La creación y la instalación de librerías se hacen una única vez.

4

Configura tu secreto y arranca el servidor

≈ 5 minutos

El archivo .env guarda tu configuración privada. Primero genera un secreto (una contraseña aleatoria que protegerá tu webhook):

terminal
# 1. Copia la plantilla de configuración
$ cp .env.example .env

# 2. Genera un secreto aleatorio (cópialo)
$ python3 -c "import secrets; print(secrets.token_hex(32))"
a3f8c2e91b...  ← copia este valor

# 3. Abre .env con cualquier editor de texto y pega el
#    valor en la línea TV_WEBHOOK_SECRET=

# 4. Arranca el servidor
$ python src/server.py
✅ DB inicializada en data/alerts/alerts.db
INFO:     Uvicorn running on http://0.0.0.0:8000
Señal de éxito Si ves la línea "Uvicorn running", tu servidor está vivo. Deja esta terminal abierta: mientras esté abierta, el servidor escucha. Para detenerlo en el futuro, pulsa Ctrl + C.
5

Prueba con alertas simuladas

≈ 3 minutos

Antes de tocar TradingView, comprueba que todo funciona con el simulador incluido. Abre una segunda terminal (deja la primera con el servidor corriendo), activa el entorno virtual de nuevo, y lanza:

terminal nº 2
$ cd ~/tradingview-mcp
$ source .venv/bin/activate
$ python tests/test_webhook.py
🧪 Enviando 10 alertas de prueba a http://localhost:8000/webhook
  #01 ✅ QQQ buy          price=484.72  → alert_id=1
  #02 ✅ SPY sell         price=539.18  → alert_id=2
  ...
✅ Completado: 10/10 alertas enviadas con éxito.

También puedes abrir http://localhost:8000/health en tu navegador: verás un JSON con el estado del servidor y la última alerta guardada.

6

Expón el servidor a internet

≈ 10 minutos

TradingView envía las alertas desde sus servidores en la nube, no desde tu navegador. Por eso necesita poder "verte" desde internet. La forma más sencilla y gratuita es un túnel:

terminal nº 2 · opción A: ngrok
# Instalar (Mac con Homebrew):
$ brew install ngrok
# Windows: descarga desde ngrok.com/download

# Crear el túnel hacia tu puerto 8000:
$ ngrok http 8000
Forwarding  https://a1b2c3.ngrok-free.app → localhost:8000

Esa URL https://...ngrok-free.app es tu dirección pública. Tu webhook completo será esa URL + /webhook, por ejemplo: https://a1b2c3.ngrok-free.app/webhook

Importante TradingView solo acepta URLs con HTTPS y puertos 80/443. El túnel ngrok ya cumple ambas condiciones, no necesitas configurar nada más. Eso sí: la URL gratuita de ngrok cambia cada vez que lo reinicias. Para una URL permanente, usa Cloudflare Tunnel (gratis) o un VPS pequeño (~4 €/mes).
Opción B: Cloudflare Tunnel (URL permanente, gratis)

1. Instala cloudflared: brew install cloudflared (Mac) o descarga desde el sitio de Cloudflare.

2. Ejecuta: cloudflared tunnel --url http://localhost:8000

3. Te dará una URL https://xxx.trycloudflare.com que funciona igual que ngrok. Para URLs con tu propio dominio, sigue la guía de "Named Tunnels" de Cloudflare.

7

Conecta TradingView y registra el MCP en Claude

≈ 10 minutos

En TradingView:

Activa la verificación en dos pasos (2FA) en tu cuenta. Sin 2FA, las alertas se disparan pero los webhooks fallan silenciosamente.
Abre tu gráfico y carga el script scripts/strategy_template.pine desde el editor Pine.
Crea una alerta: botón de reloj ⏰ → Condición: tu estrategia → marca "Webhook URL" y pega tu URL pública + /webhook.
En frecuencia, elige "Una vez por cierre de barra" para evitar señales duplicadas dentro de la misma vela.

En Claude Desktop:

Edita el archivo de configuración de Claude Desktop. La plantilla exacta está en docs/claude_desktop_config.json del proyecto; solo tienes que ajustar las rutas:

claude_desktop_config.json
// Mac: ~/Library/Application Support/Claude/
// Windows: %APPDATA%\Claude\
{
  "mcpServers": {
    "tradingview": {
      "command": "/ruta/a/tu/.venv/bin/python",
      "args": ["/ruta/a/tradingview-mcp/src/server.py", "mcp"]
    }
  }
}
Cómo encontrar tus rutas exactas Con el entorno virtual activado, ejecuta which python (Mac/Linux) o Get-Command python (Windows): esa es la ruta del "command". Para la ruta del proyecto, estando en la carpeta, ejecuta pwd.

Reinicia Claude Desktop por completo (ciérralo desde la bandeja del sistema, no solo la ventana). Al abrirlo de nuevo, verás el icono de herramientas 🔧 con tv_get_alerts, tv_get_stats y tv_analyze_signals disponibles.

Prueba final Escríbele a Claude: "Muéstrame las últimas alertas de QQQ". Si responde con las alertas simuladas del paso 5, la integración está completa. 🎉
03

Tu nuevo flujo de trabajo

Qué puedes pedirle a Claude una vez todo está conectado, y los problemas más comunes con su solución.

Herramienta · 01

tv_get_alerts

Lista las alertas guardadas con filtros por ticker, acción o estrategia. "Muéstrame las últimas 20 señales de SPY."

Herramienta · 02

tv_get_stats

Resumen rápido: total de alertas, balance buy/sell y última señal recibida. "¿Cuántas señales hubo hoy?"

Herramienta · 03

tv_analyze_signals

Diagnóstico de calidad: frecuencia, ratio buy/sell, gaps entre señales y avisos de sobre-señalización.

Solución de problemas frecuentes
La alerta se dispara pero no llega nadaComprueba que tienes 2FA activado en TradingView, que la URL termina en /webhook, y que tanto el servidor como el túnel siguen corriendo en sus terminales.
Claude no muestra las herramientasRevisa que las rutas del JSON sean absolutas (empiezan por / o C:\), que el JSON no tenga comas de más, y reinicia Claude Desktop por completo.
"Address already in use"Ya hay algo usando el puerto 8000. Cierra el proceso anterior con Ctrl+C en su terminal, o cambia TV_PORT en el archivo .env.
ngrok cambió de URLEs normal en el plan gratuito: cada reinicio genera una URL nueva. Actualiza la URL del webhook en tu alerta de TradingView, o migra a Cloudflare Tunnel para una dirección estable.
Quiero que arranque solo al encender el MacCrea un workflow en Warp (como tus startup automations) o un LaunchAgent de macOS que ejecute python src/server.py al iniciar sesión.

Seguridad: tres reglas que no se negocian

1. Nunca compartas tu TV_WEBHOOK_SECRET ni lo subas a GitHub. 2. En producción, descomenta la validación de IPs de TradingView en server.py. 3. Este sistema lee señales, no ejecuta órdenes: mantén esa separación hasta que confíes plenamente en tu estrategia, y cuando des el salto, empieza siempre en paper trading.
